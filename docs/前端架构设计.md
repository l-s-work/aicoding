# 前端架构设计

## 1. 技术栈

当前前端基于单一 Vite 项目实现 C 端和 B 端路由级隔离，技术栈如下：

- React 19
- TypeScript
- Vite
- pnpm
- React Router v7
- Zustand
- Ant Design v6
- Ant Design X
- `@ant-design/x-markdown`
- styled-components
- Axios + 原生 Fetch

设计原则：

- 轻量优先，不引入 Redux、Tailwind、复杂微前端方案
- UI 尽量复用 Ant Design 组件
- 业务状态集中在少量 Zustand Store 中
- 端隔离主要通过路由与布局壳层实现

## 3. 路由架构

### 3.1 路由划分

项目使用 `createBrowserRouter`，按角色分为三类路由：

- 公开路由
  - `/login`
  - `/register`
  - `/forgot-password`
  - `/403`
- C 端路由
  - `/`
  - `/product/:id`
  - `/cart`
  - `/checkout`
  - `/addresses`
  - `/orders`
  - `/orders/:id`
  - `/account`
- B 端路由
  - `/admin/dashboard`
  - `/admin/todos`
  - `/admin/products`
  - `/admin/products/new`
  - `/admin/products/:id/edit`
  - `/admin/orders`
  - `/admin/users`

### 3.2 懒加载策略

所有页面和布局都通过 `React.lazy` + `Suspense` 懒加载：

- C 端页面单独分块
- B 端页面单独分块
- 避免管理员页面资源被普通用户首屏加载

### 3.3 路由守卫

`PrivateRoute` 负责：

1. 判断本地是否存在 Token
2. 判断角色是否匹配
3. 调用 `/auth/me` 与后端确认会话有效性
4. 不通过时跳转 `/login` 或 `/403`

## 4. 布局设计

### 4.1 C 端布局

`ClientAppLayout` 由三部分构成：

- `ClientHeader`
- `Outlet`
- `ClientAiAssistant`

特点：

- Header 统一在壳层中管理
- 页面主体区域单独滚动
- AI 助手全局悬浮，买家端所有页面可用

### 4.2 B 端布局

`AdminAppLayout` 由两部分构成：

- `AdminHeader`
- `Outlet`

特点：

- 后台统一顶栏导航
- 内容区滚动
- 适合表格、统计和管理表单

## 6. 状态管理设计

### 6.1 `useAuthStore`

负责认证信息：

- `token`
- `user`
- `login`
- `setUser`
- `logout`

特点：

- 使用 `persist` 落地到 `localStorage`
- 给 `PrivateRoute` 与 `request.ts` 提供共享认证状态

### 6.2 `useCartStore`

负责购物车状态：

- `items`
- `addItem`
- `updateQuantity`
- `removeItem`
- `clearCart`
- `totalPrice`
- `totalCount`

当前购物车采用“商品集合”设计：

- 同一商品只保留一条记录
- 购物车页本身不维护复杂数量
- 到结算页后再调整本次下单数量

这种做法的优点：

- 前端逻辑更轻
- 不需要后端购物车表
- 与课程项目的轻量目标一致

## 7. 网络层设计

### 7.1 Axios 封装

`utils/request.ts` 是统一请求入口，职责包括：

- 设置 `baseURL=/api`
- 自动注入 Access Token
- 统一错误格式
- `401` 自动刷新
- `403` 联锁清退
- 文件上传下载封装

### 7.2 无感刷新机制

当业务请求收到 `401` 时：

1. 自动调用 `/auth/refresh`
2. 获取新的 Access Token
3. 回写 `localStorage`
4. 重放原请求

如果刷新失败：

- 清空本地授权状态
- 跳转登录页

### 7.3 SSE 流式请求

AI 对话使用原生 `fetch` + `ReadableStream`：

- 支持流式文本增量
- 支持结构化卡片事件
- 支持 AbortController 主动取消

## 8. AI 助手前端设计

`ClientAiAssistant` 是当前前端最有特色的业务组件之一。

### 8.1 交互形态

- 使用 Ant Design `Drawer` 作为主容器
- 使用 `FloatButton` 作为全局入口
- 使用 Ant Design X `Sender` 作为输入组件
- 使用 `XMarkdown` 渲染流式 Markdown 文本

### 8.2 当前支持的业务上下文

前端会把当前页面上下文传给后端：

- `page_type`
- `page_path`
- `current_product_id`
- `current_order_id`
- `cart_snapshot`

这样后端可以按当前页面判断：

- 用户是否在商品详情页
- 是否在订单列表或订单详情页
- 是否正在结算或查看地址

### 8.3 卡片渲染能力

当前已支持以下结构化卡片：

- 商品卡片
- 订单卡片
- 地址卡片
- 账号卡片
- 普通说明卡片

卡片内支持直接跳转业务页，也支持商品一键加入购物车。

## 9. 样式与组件策略

### 9.1 UI 组件原则

- 表格、表单、抽屉、弹窗、输入框等优先使用 Ant Design
- AI 交互优先使用 Ant Design X
- Markdown 优先使用 `XMarkdown`

### 9.2 样式原则

- 全项目使用 `styled-components`
- 禁止 Tailwind
- 页面样式以内聚组件为主，减少全局样式污染

## 10. 构建与代理

### 10.1 开发端口

当前前端开发默认端口是 `5180`。

### 10.2 代理规则

`vite.config.ts` 中已配置：

- `/api` -> `http://127.0.0.1:8000`
- `/uploads` -> `http://127.0.0.1:8000`

因此前端开发时：

- API 统一走 `/api/...`
- 商品图片统一走 `/uploads/...`

## 11. 当前架构优点

- 单仓库、单前端项目，维护成本低
- C/B 端通过路由和懒加载隔离，结构清晰
- Zustand 足够轻量，适合当前项目规模
- 网络层、认证、AI 流式逻辑都已集中封装
- AI 助手与电商业务页面已经真正打通，而不是独立演示组件

## 12. 当前可继续迭代的方向

- 增加更细的页面级骨架屏
- 将部分表格查询参数与 URL 联动
