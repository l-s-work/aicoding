# 前端架构设计 (Frontend Architecture)

## 1. 核心技术栈

- **前台框架**: React 19 (全面拥抱原生 Actions、`useOptimistic` 购物车乐观更新等新特性)
- **路由控制**: React Router v7 (向下兼容 v6 API，使用 `createBrowserRouter` 等标准用法)
- **全局状态管理**: Zustand (极轻量、无模板代码束缚，完美契合中小型规模)
- **UI 组件与样式**: Ant Design v6 主导业务组件（完全摒弃 Tailwind），前端排版与自定义样式采用 `styled-components` (CSS-in-JS) 方案。将样式与组件逻辑进行代码内聚，彻底规避作用域冲突，并结合 Ant Design 中基于 CSS-in-JS 的全局 Token 设计配置电商重色。
- **AI 对话组件**: Ant Design X (专用于快速构建具备 AI 交互界面的底层组件库)
- **网络层封装**: Axios (标准鉴权与业务数据请求)、Fetch API 原生调用 (专用于大模型打字机 SSE 处理)
- **打包工具**: Vite (极速冷启动和热更新)

## 3. 核心分层业务机制

### 3.1 身份认证连控鉴权 (Auth Interception)

- 围绕 `utils/request.ts` 搭建机制：在每次 `Axios Request` 将 `Zustand` 中的 Bearer Token 挂入头部。
- 设定全局 `Response` 响应拦截，对所有 HTTP `401 / 403` 异常联锁触发全局清退(`useAuthStore.getState().logout()`)，强制跳转给登录页保护资产操作重定向。

### 3.2 伴随式 AI 导购交互设计 (基于 Ant Design X)

摒弃传统硬编码搭建聊天窗，引入专属 AI 交互库 **Ant Design X** (`@ant-design/x`) 构建基于电商操作链路的全局多模态对话流。

- **沉浸式 AI 面板 (`Bubble` & `Conversations`)**：
  设计为跨路由的高层级悬浮抽屉或 Popover 组件；利用库内建的流式响应功能支持，丝滑处理底层 Fetch 发来的长连接 `Server-Sent Events (SSE)` 的切边解析。
- **高阶功能交互插槽 (`Custom Render`)**：
  打破传统的纯文本回复。前端基于 X 库监听返回结构内的 `ui_type` 或 Markdown 特殊标签：如果大模型生成意图卡片（如 `ui_type: product_cards`），则激活自定义组件插槽，在气泡内原位渲染并入 Ant Design 的 `<Card />`，使用户无需跳转即可点击「立即加购」。
- **情境级输入增强 (`Sender` & `Prompts`)**：
  应用全局共享状态上下文（Zustand）。当用户位于特定的商品页时，底部的 `Sender` 发射组件会在内部隐藏挂载当前正在浏览商品的 ID 与属性特征。这样用户的极简提问（比如："这个有其它颜色吗"）发送给后端时，AI 能产生伴随感官察觉其真实意图。

### 3.3 无缝购物车与结算设计

前端向后端发起扣减及合账计算时使用**计算分离机制**。购物车数据仅保存在 `Zustand + persist(localStorage)`，不落后端购物车表；在用户点击「去结算」时再统一向后端校验库存与价格，以后端结果为准并提交 `PlaceOrder`。

## 4. 性能优化与错误处理

### 4.1 全栈异常统一捕获

- **网络层**: `Axios` 的 `interceptors` 中统一 catch `AxiosError`，将错误转化为人话，并通过 `Antd.message` 或 `Antd.notification` 全局提示使用户免除恐慌感。
- **渲染层**: 配置最高级别的 `<ErrorBoundary>`（基于 React 的 `componentDidCatch` 概念），避免由于商品图片缺失或组件数据读取异常造成的"组件树白屏"。

### 4.2 Zustand 衍生持久化 (Persist)

对于购物车角标，通过 Zustand 天然的 `persist` 中间件对接系统的 `localStorage`。这意味着当用户多开页面时，哪怕刷新，也无需向 FastAPI 前置发起拉取购物车请求，仅在执行**去结算**动作之前再重放数据对比，降低前端心智负担和后端吞吐压力。
