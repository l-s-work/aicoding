# 商品模块设计

## 1. 模块目标

商品模块既服务 C 端买家浏览，也服务 B 端管理员维护，当前已经实现以下能力：

- 三级分类树管理
- 商品创建、编辑、查询
- 商品关键词搜索、状态筛选、分类筛选
- 商品图片上传
- 商品向量化与状态跟踪
- AI 推荐场景中的相似商品召回

## 2. 数据模型

### 2.1 分类表 `product_categories`

关键字段：

- `id`
- `category_code`
- `name`
- `parent_id`
- `level`
- `sort_order`
- `created_at`

设计特点：

- 使用三级树结构
- `category_code` 由后端自动生成
- `level` 明确记录层级，便于筛选

编码规则：

- 一级：`01`
- 二级：`01-01`
- 三级：`01-01-01`

### 2.2 商品表 `products`

关键字段：

- `id`
- `name`
- `description`
- `price`
- `stock`
- `category_id`
- `image_url`
- `tags`
- `hot_score`
- `status`
- `created_at`
- `updated_at`

说明：

- 商品必须挂在三级分类节点上
- `status` 当前为 `on_sale / off_sale`
- `tags` 使用 JSON 字符串保存
- `hot_score` 由后台人工维护

### 2.3 向量表 `product_embeddings`

关键字段：

- `product_id`
- `embedding`
- `content_hash`
- `updated_at`

说明：

- 一条商品对应一条向量
- 向量内容以 JSON 字符串方式保存在 SQLite 中

### 2.4 向量状态表 `product_embedding_statuses`

关键字段：

- `product_id`
- `status`
- `last_error`
- `retry_count`
- `updated_at`
- `last_success_at`

状态包括：

- `not_synced`
- `pending`
- `success`
- `failed`

## 3. 分类设计

### 3.1 分类创建规则

创建分类时前端只提交：

- `name`
- `parent_id`
- `sort_order`

后端自动完成：

- 判断层级
- 生成 `category_code`
- 保证最大仅三级

如果并发下发生编码冲突，后端会自动重试一次。

### 3.2 分类查询规则

当前接口：`GET /products/categories`

支持参数：

- `level`
- `category_id`
- `include_self`

支持以下能力：

- 返回完整分类树
- 返回指定分类的子树
- 返回指定层级分类
- 在指定子树范围内按层级筛选

## 4. 商品创建与编辑

### 4.1 管理端商品编辑器

页面：`/admin/products/new` 和 `/admin/products/:id/edit`

当前支持填写：

- 商品名称
- 商品描述
- 价格
- 库存
- 热度
- 状态
- 三级分类
- 单张商品图

### 4.2 分类约束

创建和编辑商品时，后端都会校验：

- `category_id` 必须存在
- `category_id` 必须是三级分类

这样可以避免商品挂在一级或二级节点上，保持分类树语义清晰。

## 5. 商品图片上传

当前接口：`POST /products/upload-image`

规则如下：

- 仅支持图片 MIME 类型
- 支持扩展名：`.jpg/.jpeg/.png/.webp/.gif`
- 单文件大小最大 5MB
- 文件保存到 `backend/uploads/products`
- 返回值为可直接访问的相对路径

前端通过 Vite 代理和后端静态文件挂载访问图片。

## 6. 商品列表查询

当前接口：`GET /products`

支持参数：

- `page`
- `page_size`
- `category_id`
- `category_ids`
- `level`
- `status`
- `keyword`

### 6.1 筛选规则

- `category_id`：单分类筛选，自动包含其子分类
- `category_ids`：多分类筛选，自动包含各自子分类
- `level`：按分类层级筛选
- `status`：按上下架状态筛选
- `keyword`：按商品名模糊匹配

### 6.2 排序规则

商品列表当前按以下顺序排序：

1. `hot_score DESC`
2. `id DESC`

## 7. C 端展示设计

### 7.1 商品列表页

页面：`/`

能力包括：

- 分类多选筛选
- 状态筛选
- 商品名搜索
- 分页
- 查看详情
- 加入购物车
- 立即购买

### 7.2 商品详情页

页面：`/product/:id`

能力包括：

- 展示价格、库存、状态、分类、描述
- 查看商品大图
- 加入购物车
- 立即购买

## 8. 管理端商品管理设计

### 8.1 商品列表页

页面：`/admin/products`

能力包括：

- 分页
- 关键词搜索
- 状态筛选
- 层级筛选
- 分类多选筛选
- 新建分类
- 新建商品
- 编辑商品
- 查看向量状态
- 手动重新向量化

### 8.2 向量状态展示

管理端会展示商品向量状态：

- 未生成
- 处理中
- 成功
- 失败

失败时可查看错误信息并手动重试。

## 9. 向量化设计

### 9.1 自动触发时机

以下场景会自动把商品标记为 `pending` 并触发后台同步：

- 新建商品
- 更新商品名称
- 更新商品描述

### 9.2 手动触发时机

管理员可通过：

- `POST /products/{product_id}/embedding/sync`

手动加入后台向量化队列。

### 9.3 设计目的

这样做可以避免：

- 每次管理端保存商品都同步等待外部模型接口
- 前端页面长时间阻塞

## 10. AI 推荐中的商品能力

商品模块不仅服务电商展示，还服务 AI 助手：

- 商品名称与描述会被向量化
- 后端可根据用户问题检索相似商品
- 可返回结构化商品卡片给前端
- 卡片支持直接跳转商品详情或加入购物车

## 11. 当前接口清单

### 11.1 分类接口

- `GET /products/categories`
- `POST /products/categories`

### 11.2 商品接口

- `GET /products`
- `GET /products/{product_id}`
- `POST /products`
- `PUT /products/{product_id}`
- `DELETE /products/{product_id}`
- `POST /products/upload-image`
- `POST /products/{product_id}/embedding/sync`

## 12. 当前模块特点

- 商品分类与商品创建强约束，避免脏数据
- 单图上传足够支撑当前作业范围
- 向量化状态透明，便于管理员排查
- 商品模块已同时服务 C 端、B 端与 AI 助手三条链路
