# 商品模块与向量匹配设计

## 1. 核心决策

### 1.1 分类层级：三级树形结构

采用邻接表模型实现灵活的三级分类（如：服装 → 男装 → 运动鞋），并在表内冗余 `level` 字段优化同层查询。

### 1.2 热度管理：后台人工设定

弃用复杂的实时统计计算（浏览、加购加权），避免高频数据库写入。采用管理员在后台主观干预的 `hot_score`（整数）模式，排序直接使用 `ORDER BY hot_score DESC`。

### 1.3 向量匹配：SQLite 存储 + Numpy 计算

针对小型电商（商品数 < 5,000）舍弃复杂的独立向量数据库（如 Pinecone 或 Milvus）。直接利用本地内存：将 OpenAI Embeddings 以 JSON 形式保存于 SQLite，由于总数据量很小，使用 Python 内置库 Numpy 直接逐个计算余弦相似度完全处于毫秒级性能，是最轻量且快速的方案。

## 2. 数据库设计 (SQLite)

本模块划分三张表，分别负责管理**分类**、**商品核心资料**和**语义向量**。

### 2.1 `product_categories` 表（商品分类树）

| 字段          | 类型    | 约束                      | 说明                                              |
| ------------- | ------- | ------------------------- | ------------------------------------------------- |
| id            | INTEGER | PK, AUTOINCREMENT         | 自增主键（数据库内部使用）                        |
| category_code | TEXT    | UNIQUE, NOT NULL, INDEX   | **业务编码**，层次结构：`01`、`01-01`、`01-01-01` |
| name          | TEXT    | NOT NULL                  | 分类名称（如"电子产品"、"手机通讯"）              |
| parent_id     | INTEGER | FK → self                 | 父级分类；`NULL` 为顶层分类                       |
| level         | INTEGER | NOT NULL                  | 1/2/3 级，直接用于前端筛选项渲染                  |
| sort_order    | INTEGER | DEFAULT 0                 | 控制同级分类展示顺序                              |
| created_at    | TEXT    | DEFAULT CURRENT_TIMESTAMP |                                                   |

**关键设计说明：**

- **`category_code` 业务编码**：采用层次化编码方案，一眼识别父子关系
  - 一级分类：`01`、`02`、`03`
  - 二级分类：`01-01`、`01-02`、`02-01`
  - 三级分类：`01-01-01`、`01-01-02`、`02-01-01`
  - **优势**：可随时添加新的一级分类（如 `04`）而不与二级/三级分类 ID 冲突，编码即代表层级结构

- **`id` vs `category_code`**：
  - `id`：数据库内部自增主键，用于外键关联（如 `products.category_id`）
  - `category_code`：业务层展示和查询字段，前端应优先展示此编码而非 ID

### 2.3 `product_embeddings` 表

独立存储向量，避免超长字符串对主表 `SELECT` 带来页面碎片和 I/O 开销。

| 字段         | 类型    | 约束                      | 说明                                                                 |
| ------------ | ------- | ------------------------- | -------------------------------------------------------------------- |
| product_id   | INTEGER | PK, FK → products.id      | 一对一关联                                                           |
| embedding    | TEXT    | NOT NULL                  | OpenAI 向量，将 1536 维浮点数组转换为 JSON 存储                      |
| content_hash | TEXT    | NOT NULL                  | 文本签名的 SHA-256：`SHA256(name + description)`，比对以防止无效的 API 调用 |
| updated_at   | TEXT    | DEFAULT CURRENT_TIMESTAMP | 向量生成或刷新时间                                                   |

## 3. 全局业务逻辑实现

### 3.1 Embedding 增量生成策略

在管理员后台 **新增或修改商品资料** 时，不直接将接口响应挂起，而是将生成请求交给事件循环后的异步线程：

```python
import hashlib
from fastapi import BackgroundTasks

def hash_content(name, description):
    # 使用 SHA-256 哈希计算内容摘要
    content_str = f"{name}:::{description}"
    return hashlib.sha256(content_str.encode('utf-8')).hexdigest()

def sync_embedding_task(product_id: int, new_hash: str, text_content: str):
    # 异步任务:
    # 1. 检查 product_embeddings 表，匹配该 product_id 的旧 content_hash
    # 2. 如果不同（或首次创建）：调用 OpenAI 获取 `text-embedding-3-small`
    # 3. 将结果 (JSON 化) UPSERT 保存至数据库
```

### 3.2 智能相似度计算流程 ( Numpy 余弦相似度 )

无需额外的向量中间件，当顾客发起询问（如："推荐几个便宜的男士衬衫"），流转如下：

1. **向量化意图：** 通过 OpenAI Embedding API 获得对话短语向量 (`query_vec`)
2. **提取候选集：** 从 SQLite 查询 `status='on_sale'` 的记录（如有明确实体，可先以 `tags` 做初步 SQL 字符串过滤）并一并读取它们的 `embedding`
3. **Numpy 本地高频检索计算（毫秒级响应）：**

```python
import numpy as np

# query_vec 来源自 OpenAI (长度 1536 的数组)
# db_records 是从数据库取出的数组，每条包含 product_id 及 JSON 形式的 embedding
candidates = []
for row in db_records:
    # 将 JSON 转换回并组装为 numpy 矩阵
    item_vec = np.array(json.loads(row['embedding']))
    candidates.append((row['product_id'], item_vec))

# 使用 numpy 广播或迭代计算余弦值
q_np = np.array(query_vec)
results = []
for pid, vec in candidates:
    cosine_sim = np.dot(q_np, vec) / (np.linalg.norm(q_np) * np.linalg.norm(vec))
    results.append((cosine_sim, pid))

# 对相似度得分排序并提取前 Top 5
results.sort(key=lambda x: x[0], reverse=True)
top_5_product_ids = [pid for score, pid in results[:5]]
```

4. **提供给 大语言模型(LLM)：** 将提取出的商品清单组装送入大模型 prompt 上下文中返回自然响应。

## 4. 后台商品与类目管理接口

| 视图类型     | 方法  | 路径                             | 说明                                    |
| ------------ | ----- | -------------------------------- | --------------------------------------- |
| 分类管理     | GET   | `/admin/categories/tree`         | 获取完整三级类目树                      |
| 分类管理     | POST  | `/admin/categories`              | 新建单条分类 (指定 parent_id)           |

| 商品库管理   | PUT   | `/admin/products/{id}`           | 编辑；更改 name/desc 更新向量，包含热度 |
| 商品热度管理 | PATCH | `/admin/products/{id}/hot_score` | 快捷通道直接修改商品热度分数            |

## 5. 小结论证

本套基于人工设定热度及极简内存矩阵算子(`Numpy`) 的工程设计方案：

- 极其符合微型电商（极低的并发操作、不需要繁杂指标日志追踪）的项目环境。
- 将成本大头聚集在只为必须发生的文本变更调起 OpenAI Embed，不被毫无变化的内容白屏重查，最大程度保护账户限额。
