# 库存并发设计

## 1. 并发问题分析

### 场景一：同一用户重复提交

用户网络卡顿时多次点击"下单"，可能短时间内发出多个相同请求。

**处理：**

- 前端：点击下单后立即Loading按钮，收到响应后恢复（无论成功或失败）
- 后端：原子 UPDATE 自然保证只有一个事务能扣减成功，其余返回 400

### 场景二：多用户同时购买同一件库存为 1 的商品（核心问题）

**不安全的做法（先查后改）会出现竞争窗口：**

```
用户A: SELECT stock FROM products WHERE id=1 → stock=1
用户B: SELECT stock FROM products WHERE id=1 → stock=1   ← 还没被A更新
用户A: UPDATE products SET stock=0 WHERE id=1 → OK
用户B: UPDATE products SET stock=0 WHERE id=1 → OK       ← 超卖！实际库存变成 -1
```

**解决：使用 Atomic UPDATE（条件更新）**

---

## 2. 核心方案：原子 UPDATE

### 2.1 SQL 写法

```sql
UPDATE products
SET stock = stock - :quantity
WHERE id = :product_id
  AND stock >= :quantity
```

这条 UPDATE 在 SQLite 中是 **原子操作**：读-改-写在数据库引擎内部一步完成，不存在竞争窗口。

执行后检查 `cursor.rowcount`：

| rowcount | 含义                               | 处理                                                    |
| -------- | ---------------------------------- | ------------------------------------------------------- |
| 1        | 扣减成功                           | 继续创建订单，COMMIT                                    |
| 0        | 库存不足（被别人抢先，或本就不够） | ROLLBACK，返回 `400 {"detail": "库存不足，请重新选购"}` |

### 2.2 为什么 SQLite 不会超卖？

SQLite 采用文件级写锁（WAL 模式下为写锁），同一时刻只有一个写事务可以执行，其余等待。因此不存在两个 UPDATE 真正并行执行的情况。

原子 UPDATE 的作用是从应用层消除"先查后改"的竞争窗口——只要代码里不出现单独的 SELECT stock 再 UPDATE，数据层面就不会超卖。

## 3. 完整订单创建事务流程

```
POST /orders 请求到达
         │
         ▼
BEGIN IMMEDIATE TRANSACTION
（立即获取写锁，阻止其他写事务并发进入，确保步骤串行执行）
         │
         ├─ Step 1：原子扣减库存
         │    UPDATE products SET stock=stock-qty WHERE id=? AND stock>=qty
         │    rowcount == 0 → ROLLBACK → 返回 400 "库存不足，请重新选购"
         │
         ├─ Step 2：查询并校验收货地址归属
         │    SELECT * FROM user_addresses WHERE id=? AND user_id=?
         │    不存在 → ROLLBACK → 返回 404
         │
         ├─ Step 3：INSERT INTO orders
         │    （含 receiver_info 地址 JSON 快照、总金额、状态='pending'、创建时间）
         │
         ├─ Step 4：INSERT INTO order_items
         │    （每件商品一条：product_id, product_name, quantity, buy_price 下单时价格快照）
         │
         └─ COMMIT
                  │
                  ▼
         返回 201 { order_id, status: "pending", total_amount }
```

### 价格快照说明

`order_items` 中存储下单时的 `buy_price`（符合 AGENTS.md 规范），不通过外键引用 `products.price`，防止商家后续改价导致历史订单金额错位（与地址快照原理相同）。

## 4. SQLite 性能配置 (SQLAlchemy 2.0 Async)

### 4.1 数据库连接与 WAL 模式

使用 SQLAlchemy 2.0 异步引擎（`aiosqlite` 驱动），在连接事件中开启 WAL 模式：

```python
# app/db/database.py
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession
from sqlalchemy import event

# SQLite 异步连接，关闭同线程校验
DATABASE_URL = "sqlite+aiosqlite:///./app.db"

engine = create_async_engine(
    DATABASE_URL,
    connect_args={"check_same_thread": False},
    echo=False,
)

# 连接时自动开启 WAL 模式与外键约束
@event.listens_for(engine.sync_engine, "connect")
def set_sqlite_pragma(dbapi_conn, connection_record):
    cursor = dbapi_conn.cursor()
    cursor.execute("PRAGMA journal_mode=WAL")      # WAL 模式：读写互不阻塞
    cursor.execute("PRAGMA foreign_keys=ON")        # 启用外键约束
    cursor.execute("PRAGMA busy_timeout=5000")      # 写锁等待超时 5 秒
    cursor.close()

# 异步 Session 工厂
AsyncSessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db() -> AsyncSession:
    """FastAPI Depends 依赖注入：获取异步数据库会话"""
    async with AsyncSessionLocal() as session:
        yield session
```

**WAL vs 默认 DELETE 模式对比：**

| 模式            | 读写并发             | 适用场景                |
| --------------- | -------------------- | ----------------------- |
| DELETE（默认）  | 写操作期间阻塞所有读 | 几乎无并发的场景        |
| **WAL（推荐）** | 读写互不阻塞         | 有并发读请求的 Web 应用 |

### 4.2 订单创建完整事务 (SQLAlchemy 2.0 Async)

使用 SQLAlchemy ORM 的异步会话直接操作，无需手动 `run_in_executor`：

```python
import json
import random
from datetime import datetime
from sqlalchemy import update, select, text
from fastapi import HTTPException

async def create_order(db: AsyncSession, order_data: dict, user_id: int):
    """
    创建订单的完整事务（含原子库存扣减）
    使用 SQLAlchemy 2.0 async session，自动管理事务生命周期
    """
    await db.execute(text("BEGIN IMMEDIATE"))
    try:
        # Step 1：原子扣减库存（条件更新，防超卖）
        for item in order_data["items"]:
            result = await db.execute(
                update(Product)
                .where(Product.id == item["product_id"], Product.stock >= item["quantity"])
                .values(stock=Product.stock - item["quantity"])
            )
            if result.rowcount == 0:
                raise HTTPException(400, f"商品 {item['product_id']} 库存不足，请重新选购")

        # Step 2：查询并校验收货地址归属
        addr_result = await db.execute(
            select(UserAddress).where(
                UserAddress.id == order_data["address_id"],
                UserAddress.user_id == user_id
            )
        )
        addr = addr_result.scalar_one_or_none()
        if not addr:
            raise HTTPException(404, "收货地址不存在")

        # Step 3：拍屏式硬拷贝地址为 JSON（符合 AGENTS.md receiver_info 规范）
        receiver_info = json.dumps({
            "receiver_name": addr.receiver_name,
            "phone": addr.phone,
            "province": addr.province,
            "city": addr.city,
            "district": addr.district,
            "detail_address": addr.detail_address,
        }, ensure_ascii=False)

        # 生成订单号：冲突重试（最多 5 次）
        order_no = None
        for _ in range(5):
            candidate = datetime.now().strftime("%Y%m%d") + \
                        str(user_id).zfill(4)[-4:] + \
                        str(random.randint(100000, 999999))
            exists = await db.execute(select(Order.id).where(Order.order_no == candidate))
            if exists.scalar_one_or_none() is None:
                order_no = candidate
                break
        if order_no is None:
            raise HTTPException(500, "订单号生成失败，请稍后重试")

        new_order = Order(
            order_no=order_no,
            user_id=user_id,
            total_amount=order_data["total_amount"],
            status="pending",
            receiver_info=receiver_info,
        )
        db.add(new_order)
        await db.flush()  # 获取 order.id

        # Step 4：创建订单明细（含 buy_price 价格快照）
        for item in order_data["items"]:
            order_item = OrderItem(
                order_id=new_order.id,
                product_id=item["product_id"],
                product_name=item["product_name"],
                quantity=item["quantity"],
                buy_price=item["buy_price"],  # 永久固化下单时的购买价格
            )
            db.add(order_item)

        await db.commit()
    except:
        await db.rollback()
        raise

    # 事务提交成功
    return {"order_id": new_order.id, "order_no": order_no, "status": "pending"}
```

## 5. 前端防重复提交

```jsx
// React 下单按钮示例
const [submitting, setSubmitting] = useState(false);

const handleCheckout = async () => {
  if (submitting) return; // 防止重复触发
  setSubmitting(true);
  try {
    const res = await api.post("/orders", orderData);
    navigate(`/orders/${res.data.order_id}`);
  } catch (err) {
    if (err.response?.status === 400) {
      toast.error(err.response.data.detail); // "库存不足，请重新选购"
    } else {
      toast.error("下单失败，请稍后重试");
    }
  } finally {
    setSubmitting(false); // 无论成功失败都恢复按钮
  }
};

<button onClick={handleCheckout} disabled={submitting}>
  {submitting ? "提交中..." : "确认下单"}
</button>;
```

## 6. 总结

| 问题                  | 解决方案                                      | 复杂度 |
| --------------------- | --------------------------------------------- | ------ |
| 多用户抢购同一库存    | 原子 UPDATE + `rowcount` 校验                 | 低     |
| 同一用户重复下单      | 前端禁用按钮 + 原子 UPDATE 后端保底           | 低     |
| 应用层竞争窗口        | `BEGIN IMMEDIATE` 事务                        | 低     |
| 异步框架阻塞问题      | SQLAlchemy 2.0 Async + aiosqlite              | 低     |
| 历史订单价格/地址固化 | 下单时快照 `buy_price` + `receiver_info` JSON | 低     |

> **结论**：对于 SQLite + 单进程 FastAPI 的小型电商项目，原子 UPDATE 方案已完全覆盖库存并发问题，无需引入 Redis 分布式锁或消息队列。使用 SQLAlchemy 2.0 Async 引擎与 FastAPI 原生 async 无缝配合，无需手动线程池调度。
