# 收货地址模块详细设计

## 1. 核心决策

### 1.1 为何独立建表？

用户可能拥有多个收货地址（家、公司、父母家等），与订单是 **一对多** 关系。地址信息不属于用户基本信息，拆分成独立表符合第三范式，便于独立维护 CRUD。

### 1.2 为何订单存快照而非 FK？

| 方案                                | 说明                             | 问题                                                           |
| ----------------------------------- | -------------------------------- | -------------------------------------------------------------- |
| 订单存 address_id (FK)              | 引用 user_addresses 表           | 用户修改/删除地址后，历史订单地址随之变化，违背商业逻辑        |
| **订单存地址快照（✅ 本项目选用）** | 下单时将地址字段复制进 orders 表 | 历史订单地址永久固化，符合所有主流电商实践（京东、淘宝均如此） |

## 2. 数据库表设计

### user_addresses 表

| 字段           | 类型    | 约束                      | 说明                |
| -------------- | ------- | ------------------------- | ------------------- |
| id             | INTEGER | PK, AUTOINCREMENT         |                     |
| user_id        | INTEGER | FK → users.id, NOT NULL   | 所属用户            |
| receiver_name  | TEXT    | NOT NULL                  | 收货人姓名          |
| phone          | TEXT    | NOT NULL                  | 手机号              |
| province       | TEXT    | NOT NULL                  | 省                  |
| city           | TEXT    | NOT NULL                  | 市                  |
| district       | TEXT    | NOT NULL                  | 区/县               |
| detail_address | TEXT    | NOT NULL                  | 详细街道门牌        |
| is_default     | INTEGER | DEFAULT 0                 | 是否默认地址（0/1） |
| created_at     | TEXT    | DEFAULT CURRENT_TIMESTAMP |                     |

### orders 表中的地址快照字段

订单创建时将地址信息以拍屏式硬拷贝写入 orders 表的单一 JSON 字段，**不存 address_id 外键**：

| 字段          | 类型 | 说明                                                                                                    |
| ------------- | ---- | ------------------------------------------------------------------------------------------------------- |
| receiver_info | TEXT | 拍屏式地址快照（JSON 字符串，包含 receiver_name / phone / province / city / district / detail_address） |

存储示例：

```json
{
  "receiver_name": "张三",
  "phone": "13800138000",
  "province": "广东省",
  "city": "深圳市",
  "district": "南山区",
  "detail_address": "科技园路1号"
}
```

## 3. 业务规则

### 3.1 地址数量上限（最多 5 个）

新增接口前端收集表单，后端在 INSERT 前先校验：

```sql
SELECT COUNT(*) FROM user_addresses WHERE user_id = :user_id
```

若结果 ≥ 5，返回 `400 {"detail": "最多保存5个收货地址"}`

### 3.2 is_default 唯一性保证

`is_default=1` 在同一用户下只能存在一条，使用 **SQLite 事务** 保证原子性：

```sql
BEGIN TRANSACTION;
  -- 先将该用户所有地址置为非默认
  UPDATE user_addresses SET is_default = 0 WHERE user_id = :user_id;
  -- 再将目标地址置为默认
  UPDATE user_addresses SET is_default = 1 WHERE id = :address_id AND user_id = :user_id;
COMMIT;
```

并在数据库层增加兜底约束（防止并发下出现双默认）：

```sql
CREATE UNIQUE INDEX uq_user_default_address
ON user_addresses (user_id)
WHERE is_default = 1;
```

### 3.3 初次新增自动设为默认

新增地址时检查该用户地址数量：若当前为 0 条，则 `is_default` 自动置为 1（第一个地址必然是默认）。

### 3.4 删除默认地址处理

- 若删除的是默认地址，则自动将 `created_at` 最新的一条地址设为新默认
- 若用户地址只剩 1 条且被删除，则该用户无默认地址（前端下单时提示"请先添加收货地址"）

### 3.5 下单时地址快照

在 `POST /orders` 接口的事务中，将地址信息以拍屏式 JSON 硬拷贝写入订单的单一 `receiver_info` 字段：

```python
import json

# 1. 查询用户选定的地址（校验归属）
addr = await db.execute(
    select(UserAddress).where(
        UserAddress.id == address_id,
        UserAddress.user_id == user_id
    )
)
addr_row = addr.scalar_one_or_none()
if not addr_row:
    raise HTTPException(404, "地址不存在")

# 2. 拍屏式硬拷贝地址信息为 JSON 字符串（符合 AGENTS.md receiver_info 规范）
receiver_info = json.dumps({
    "receiver_name": addr_row.receiver_name,
    "phone": addr_row.phone,
    "province": addr_row.province,
    "city": addr_row.city,
    "district": addr_row.district,
    "detail_address": addr_row.detail_address,
}, ensure_ascii=False)

# 3. INSERT INTO orders 时携带单一 receiver_info JSON 字段（不存 address_id 外键）
new_order = Order(
    user_id=user_id,
    receiver_info=receiver_info,
    total_amount=total_amount,
    status='pending'
)
db.add(new_order)
```

## 4. 接口清单

| 方法   | 路径                               | 鉴权     | 说明                             |
| ------ | ---------------------------------- | -------- | -------------------------------- |
| GET    | `/addresses`                       | 登录用户 | 查询当前用户所有收货地址         |
| POST   | `/addresses`                       | 登录用户 | 新增地址（校验 ≤5 个限制）       |
| PUT    | `/addresses/{id}`                  | 登录用户 | 编辑地址（校验归属当前用户）     |
| DELETE | `/addresses/{id}`                  | 登录用户 | 删除地址（处理默认地址自动迁移） |
| POST   | `/addresses/{id}/set-default`      | 登录用户 | 设为默认（事务原子更新）         |

### 安全要点

- 所有接口均验证 `address.user_id == current_user.id`，防止越权操作他人地址
- 编辑/删除时使用 `WHERE id=? AND user_id=?`，不匹配则统一返回 404（防止信息泄露）

## 5. 前后端交互流程

```
【查看地址列表】
前端：GET /addresses
后端：返回 [ { id, receiver_name, phone, province, city, district, detail_address, is_default } ]

【结算页选择地址】
前端：展示地址列表 → 用户选择其中一个
下单请求携带：{ address_id: 3, cart_items: [...] }
后端：验证地址归属 → 快照进订单 → 与库存扣减在同一事务中完成

【添加新地址】
前端：填写表单 → POST /addresses
后端：校验数量上限 → INSERT → 返回新地址对象（含 id 字段供前端更新列表）

【设为默认】
前端：点击"设为默认" → POST /addresses/3/set-default
后端：事务内先全置 0 再置目标为 1 → 返回 200
```
