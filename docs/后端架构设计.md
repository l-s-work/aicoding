# 后端架构设计 (Backend Architecture)

## 1. 业务级核心栈

- **核心框架引擎**: Python FastAPI (卓越的协程性能、高规格类型输入约束及 OpenAPI 标准化暴露)
- **底层数据库依赖**: SQLite (拒绝 Redis 以简化并迎合极小型微商架构)
- **ORM 数据映射**: SQLAlchemy 2.0 (全盘使用新版映射与异步游标策略)
- **参数控制校验链**: Pydantic v2
- **安全体系加密锁**: Bcrypt (密码散列化) + PyJWT (基于 HS256 签发 Access & Refresh Token)
- **大语言整合底座**: OpenAI 官方接口 + Numpy（进行内部小型本地化商品库召回预计算）

## 3. 分层模块架构实现细节

### 3.1 高安全标准的 JWT（轻状态校验）

不引入 Redis。鉴权采用 `JWT + SQLite 拦截表` 的轻状态方案：
- Access Token 内含 `token_version + jti`。
- `deps.get_current_user` 先验签，再校验 `token_version`（全设备踢出）与 `access_token_blocklist`（单设备主动登出即时失效）。
- Refresh Token 仅存 `HttpOnly Cookie`，其 SHA-256 哈希存于 `refresh_tokens`，支持精准失效与续签。

### 3.2 订单落库与安全锁扣防超卖机制 (无 Redis)

- SQLite 拒绝高并发长事务切片。架构决定所有的库存减量只执行 **原子锁级合并**:
  _执行 `query() -> update()` 非安全；变更为强制： `UPDATE products SET stock = stock - N WHERE id = ? AND stock >= N`_
- 利用 `cursor.rowcount` 返回行影响数量确定扣件状态成功。一旦返回 0 ，抛出库存不足等错误指令触发外层 SQLAlchemy async session 自动 `.rollback()` 机制放弃订单插入。
- 在最终插入 Order 库表时明确进行“文本级别的快照解耦”：地址以 `receiver_info` JSON 字段拍屏式硬拷贝，价格以 `buy_price` 字段固化到 order_items。

### 3.3 极轻量 AI 并发对话导流 (AI Integration)

通过 `text-embedding-3-small` 将录入商城的商品特性抽成向量（存储至 SQLite 一列内串化的 JSON），抛离重模式向量库（如 Milvus / pinecone 等）。
客户发出聊天：调用端侧内存层导入该类别向量 `Numpy Matrix` 对比出高相关分数物品 (`cosine_similarity`) -> 推入 OpenAI 大模型包装层，经其思考给出带有人设与促销口吻文字并附加特定的 JSON 渲染模板。最终挂载向 `FastAPI StreamingResponse` 输出流式序列完成向 React 侧响应。
